About this machine

You are reading this on a 32-bit RISC-V computer that exists only as a pixel shader. Its processor, its memory and its graphics card are textures that fragment shaders rewrite every frame. It boots Linux, and this browser is an ordinary Linux program.

How a page gets here

  1. The browser writes an address into a few words of memory.
  2. The host, which is the program running the shader, sees them and fetches the page.
  3. The host puts the page into the machine's memory in one shader pass.
  4. The browser reads it and lays it out.

The processor runs about three million instructions a second, so everything that can be done in parallel is done by hardware: drawing, windows, text, copies of memory, pictures.

That picture is not decoded or copied by the processor at all: the graphics card samples it from the file where it lies in the ROM.
